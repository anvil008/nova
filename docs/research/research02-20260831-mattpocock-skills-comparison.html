Workcell's skills are strong on orchestration process (dispatch contracts, deterministic merge/render scripts, human gates, evals) but carry almost no code-design method: the only architecture vocabulary in the repo is two sentences in code-refactor, code-review has no architecture lens, and reviewer agents get four vague style flags. mattpocock/skills supplies exactly the missing layer — codebase-design is a portable, closed-glossary design method (depth-as-leverage, the deletion test, seam/adapter rules, testability rules, a 4-tier dependency classification) and improve-codebase-architecture is a report-first architecture-audit workflow whose shape (git-history scoping, sub-agent exploration, HTML candidate report for human triage, ADR-conflict policy) maps almost one-to-one onto patterns Workcell already has. Port the content — the glossary, principles, and workflow steps — into Workcell's existing skill shapes (references/ files, lenses, research/refactor survey steps) rather than importing the single-agent skills wholesale.

highR-01Port the codebase-design glossary and principles as a shared design-heuristics reference

Create a design-heuristics reference (e.g. skills/code-refactor/references/design-heuristics.md, cross-linked from code-review and plan) carrying the closed glossary (module, interface, depth, seam, adapter, leverage, locality — with banned synonyms), the four principles (depth is a property of the interface; the deletion test; the interface is the test surface; one adapter = hypothetical seam, two = real), the three testability rules, and DEEPENING.md's 4-tier dependency classification. This fills the repo's only real content gap: no skill or doc currently teaches a design method, and code-refactor/code-analysis are SKILL.md-only with no references/ today.

06

Method

Step 1

Area split

The goal is decomposed into genuinely distinct areas — by subsystem, source type, or question. The fan-out count equals the number of real areas, never a fixed N.

Step 2

Blind fan-out

One read-only researcher agent per area, in parallel. Each is confined to its area and returns a strict findings envelope with evidence.

Step 3

Deterministic merge

Deduplicated by (area, source, finding). Conflicts are surfaced when a topic carries more than one position; coverage, gaps, and open questions are rolled up.

Step 4

Synthesis

The primary agent owns the conclusion and recommendations. Evidence from the areas is cited, never inherited as a verdict.

●

Research output is evidence, not authority. The primary agent running the research owns the consolidated conclusion.
