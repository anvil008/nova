Workcell / comparison review

Who gives the graph its meaning?

Herdr Dagr and Workcell both display recorded work. The agent decides what the work is. Their biggest differences are how facts reach the file and how relationships are represented.

7 September 2026 · Herdr source review and current Workcell implementation · Local report

CLI commands record task meaning. The adapter adds observed session metadata and attributable usage.

Hooks cannot decide that a feature is complete. They can report that a session started, stopped, or produced usage data. Producer source · Plugin source
02

Names come from the producer

Herdr’s convention

L1       impl: core lane
R1       review: core lane
G1       gate: integrate
L1·a2    another attempt at L1

The producer chooses IDs and titles. L/R/G are examples, not required prefixes. Model chips are supplied text, often shortened to model·effort. Source

Workcell’s current guidance

cache     Fix cache expiry
storage   Compare storage options
cache.a2  Fix cache expiry
verify    [M1 · #42] Verify login

Short stable IDs and concrete titles. First-attempt suffixes and empty group labels stay out of graph rows. Brackets appear only for recorded milestones or issue links.

Names above are examples. Task IDs identify work; attempt IDs identify a try at it; session IDs identify runtime sessions. A GitHub issue link is a reference, not automatic issue synchronization.

04

How the file changes

Herdr: producer writes the document

Prepare run.json.tmp
↓
dagr check --strict --json
↓ only after validation succeeds
Atomically replace run.json

Start records an attempt. Settlement records outcome, timing, and evidence. Retry appends history. Source

Workcell: commands perform the write

task add / set / retry · session bind · usage
↓
Lock → read → change → validate
↓
Atomic replacement → viewers refresh

The producer uses commands instead of rewriting the full document. The collector uses the same validation and storage functions.

What “done” means

Herdr records four evidence tiers: verified, reported, heuristic, asserted. Runtime disappearance alone is not a completion claim. Source

Workcell requires an evidence reference for done. Its verified flag is a producer assertion; the viewer does not run the check itself. Stop hooks leave task outcomes unchanged.

06

What is still missing or unverified

Known Workcell gaps

  • Implemented: retry-cause references, explicit gates, and preserved attempt inputs.
  • Nested groups, recursive folding, zoom, and an attention queue.
  • Implemented: structured progress counts and question tasks that show “needs answer”.
  • Cross-workspace run routing and aggregation.
  • Claude/Agy telemetry adapters.

Verification limits

  • Upstream source was inspected; every native interaction was not exercised.
  • Workcell’s Codex plugin is installed. This existing conversation uses a temporary watcher; native hooks require a restarted session.
  • Automatic child-session capture still needs an end-to-end native-session check.
  • Codex transcript format may change. Missing telemetry must remain unknown.
Core reliability update: cause references, explicit task kinds, progress counts, bounded storage, and attempt input history are implemented. Next: decide cross-workspace routing and other harness telemetry. Conditional policies and pane messaging remain optional.
