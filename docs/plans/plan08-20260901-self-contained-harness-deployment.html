Self-contained harness deployment

REFRAMED GOAL (supersedes the previous revision of this plan): every Nova artifact a harness or project consumes at runtime — the plugin in all four harnesses, the tdd-guard binary, and the hook/CLI wrappers — becomes a deployed, version-identifiable copy; the repository working tree is needed only to build and stage, never at runtime. The prior revision deliberately left ~/.local/bin/build-hooks, build-format, build-lint, build-guard and nova-ws as live symlinks (scripts/bootstrap-tools.sh:87-93, pinned at scripts/tests/test_install.sh:78-81); that non-goal is now in scope. Verified feasible: none of the five wrappers nor nova-ws sources scripts/lib.sh or dereferences $ROOT at runtime, so a copy runs standalone.

GROUND TRUTH, verified on this machine (CLIs: claude 2.1.252, codex 0.151.0, agy 1.1.23, grok 1.0.13). Claude's cached plugin is already a self-contained copy (~/.claude/plugins/cache/nova/{0.4.0,0.5.0,0.6.0}, zero symlinks) but known_marketplaces.json records source AND installLocation /home/anvil/repos/nova — a live pointer with no snapshot. Codex caches a symlink-free copy keyed by manifest version (~/.codex/plugins/cache/nova/nova/0.1.0+codex.20260830065625) but its marketplace resolves $ROOT/dist/codex, a gitignored build directory. Grok's installed copy is real (~/.grok/installed-plugins/nova-87b7a35e) but registry.json records source_url_or_path: $ROOT/dist/grok — the same gitignored coupling. Antigravity is two live symlinks into $ROOT/plugins/agy (bootstrap-plugins.sh:119-122,146-149) plus a third per project (bootstrap-project.sh:77); agy plugin list prints "No imported plugins" with both present, while agy plugin validate plugins/agy reports ok (skills:15 agents:10 hooks:1). tdd-guard is a symlink from ~/.local/bin into gitignored $ROOT/bin/tdd-guard with no version anywhere (guard/guard.go:25-26 names only the status contract).

DESIGN DECISIONS, each chosen between two. (1) Copy ownership: the prior revision's receipt-backed install_owned / uninstall_owned / owned_copy / installed_version under ${NOVA_STATE:-$HOME/.local/state/nova}/receipts/ with a .nova-stamp.json in staged trees is REUSED unchanged — it already won a design-twice against digest-vs-$ROOT ownership (a digest comparison dies with the working tree, the very dependency this milestone removes), and this redo extends it with one helper, nova_share_dir (${NOVA_SHARE:-$HOME/.local/share/nova}), the durable staging area the new Claude and Codex marketplace roots live in. (2) Claude: command-source marketplace versus a durable staged directory marketplace. A directory marketplace at a durable path keeps every behaviour documented but keeps the seam where this repository's staleness bugs actually live — a directory someone must keep fresh, defeated by version-keyed caching (docs: same version, users keep the cached copy; a non-git local dir resolves "unknown" and updates are never detected) and refreshed today by a destructive uninstall/install pair. The command plugin source with "mode": "copy" (docs fetched 2026-09-01; CLI 2.1.229+, local is 2.1.252, and claude plugin install --help confirms --yes exists precisely to accept a command-declared plugin non-interactively) inverts the seam: the marketplace names a producer, Claude copies its output, versions it by CONTENT HASH, and re-runs it once per session in the background and on install/update/cache-miss — retiring manual version bumps and the destructive refresh in one move. The producer bootstrap writes is a durable shim that restages from the repository when it exists and replays the last staged durable tree when it does not, so the undocumented repo-gone failure mode never reaches Claude: the command always prints one line and exits 0. Command source wins on depth (refresh disappears as a human ceremony), seam (the one-line-producer contract is an interface Claude itself documents) and locality (staging logic in one new build-claude-plugin.py plus one shim). Cost: disableCommandPluginSources can forbid it — carried as a risk with a documented directory-source fallback from the same durable tree. (3) Grok: durable staged marketplace versus the documented drop directory. The vendored user guide (xai-org/grok-build, 09-plugins.md) documents ~/.grok/plugins/ as user-scope, auto-discovered AND auto-trusted; the drop wins because it deletes the worst coupling in the system (a registry entry naming gitignored dist/grok), removes the uninstall/reinstall refresh hack (version is optional metadata only, so the marketplace flow can never detect updates), and lands on the same shape as Antigravity: one owned copy at a harness-documented path. (4) Antigravity: ADR 0006's premise is stale — agy plugin commands are now documented (antigravity.google/docs/cli/plugins/) — but the CLI installs into a directory whose scan status is undocumented and its registry does not see scanned plugins, while dropping a folder at ~/.gemini/config/plugins/ IS the documented supported install. So: one owned copy at the documented scan directory; both legacy symlinks are deleted by our own installer (never by agy plugin uninstall, which is undocumented against a pre-existing symlink and must not purge through it); the ~/.gemini/antigravity-cli/plugins/nova location is retired rather than duplicated, because two distinct copies — unlike two symlinks resolving to one target — are a double-loading surface (the exact bug class agy fixed for symlinks in v1.1.3). Codex is not contested: it keeps the only flow its CLI documents (marketplace add/remove, verified against codex plugin --help), but the registered root moves to an owned durable copy and the staged manifest version becomes <tracked semver>+codex.<content-hash>, keeping the accidental content-varying refresh protection deliberately and closing ADR 0021's "Codex version cannot confirm a release" consequence.

ASSUMPTIONS, stated rather than asked. (a) The durable staging area is ~/.local/share/nova/ and receipts stay under ~/.local/state/nova/; both derive from $HOME so the throwaway-HOME test harness stays hermetic. (b) The release version is 0.6.0 everywhere; plugins/agy/plugin.json (0.1.0) and plugins/codex/.codex-plugin/plugin.json (buildstamped) converge on it inside the issues that own them. (c) The repo-root marketplace manifests .claude-plugin/marketplace.json and .agents/plugins/marketplace.json are deleted once nothing registers them — leaving a registration-shaped file that points into the working tree would be exactly the live pointer this milestone exists to remove. (d) Full self-containment was found coherent for every piece — no needs-decision remains: the wrappers copy cleanly, and each harness has a documented copy-shaped mechanism.

◇

The decision record superseding ADR 0006's Antigravity clause and re-grounding ADR 0021 per harness on the fresh upstream documentation, plus every document and doc-truth test that must match it.

What changes

Nothing about what the gates prove changes; what changes is where a running harness reads Nova from, and what a deploy leaves behind. Today the four harnesses split three ways: Claude and Codex hold self-contained cache copies but resolve refreshes through registrations that point at the working tree or its gitignored dist/; Grok holds a copy whose registry names dist/grok; Antigravity and every `~/.local/bin` tool are live symlinks into the tree. After this milestone every runtime read lands on an owned, version-identifiable copy: Claude installs from a durable command-source marketplace whose shim restages when the repo exists and replays the last staged tree when it does not (content-hash versioned, refreshed once per session by the harness itself); Codex installs from an owned durable marketplace tree with a `<semver>+codex.<content-hash>` staged version; Grok and Antigravity get owned copies at their documented auto-discovery directories with no registration at all; `tdd-guard` (now carrying `guard.Version`), the four hook wrappers and `nova-ws` install as receipt-owned copies; CI publishes versioned guard artifacts so a machine without a checkout can install the gate. Ownership — what lets an uninstall remove our files and refuse everyone else's — moves from 'symlink whose target is inside $ROOT' to receipts plus on-disk stamps, and drift becomes visible: stamps carry versions, `bootstrap-tools.sh` reports installed-versus-repo drift, and a bootstrap re-run re-stages everything.

Wave 1guard/**planningtype:featureguardcli
▾

## Goal

tdd-guard carries no build version at all. The only version-shaped constant in the package is guard.APIVersion = "anvil.guard/v1" (guard/guard.go:25-26), which names the status --json contract, not the build. Once the binary is a copy rather than a symlink there is nothing on disk that says which release it is, and no way to detect a stale install. Give the binary a version it can print, and make it printable from anywhere — an installed guard usually runs from $HOME, and today an unknown subcommand falls into dispatch, calls loadState (guard/run.go:92), fails to resolve a repository root and exits 1.

## Scope

- New guard/version.go: - const Version = "0.6.0" — the semver single source of truth for the release, matching plugins/claude/.claude-plugin/plugin.json and the v0.6.0 tag. It lives in Go source, not only in ldflags, so a plain go build ./... still produces a binary that tells the truth. - var BuildMetadata string, settable with -ldflags "-X github.com/anvil008/nova/guard.BuildMetadata=<commit>". It *appends* (0.6.0+abc1234) and never replaces the semver, so an unstamped build degrades to a correct 0.6.0, not to dev or an empty string. - func VersionString() string composing the two. - guard/run.go: handle version (plus --version / -v aliases) before any loadState call, alongside the existing --help short-circuit at lines 52-55, so it never needs a repository. Output is exactly tdd-guard <VersionString()> on stdout, exit 0. Add version to usageCommands (guard/run.go:14-22). - Tests in guard/version_test.go.

## Constraints

- Do not change guard.APIVersion or any status --json field; the control-plane contract is untouched. - No new dependency; go.mod lists none today and go.sum stays empty. - --version must not read, create or require any state directory.

CopyOwnershipscripts/lib.sh can own a copied file or tree, not only a symlink
Wave 1scripts/**planningtype:featureinstallerportability
▾

## Goal

Every installer decision runs through one question: is the thing at this destination ours? Today the answer is owned_link (scripts/lib.sh:11) — 'a symlink whose literal target is inside $ROOT'. A copy cannot answer that question, so before anything is converted, lib.sh needs the copy-side equivalent with the same three behaviours the link side guarantees: install only over absent-or-ours, refuse a foreign destination by name with a non-zero return, and remove on uninstall only what we installed while reporting what was left behind.

## Scope — scripts/lib.sh only; no caller changes in this issue

Add, beside the existing link helpers:

- install_owned SRC DST VERSION [--force] — copies a regular file (mode 0755) or a directory tree to DST when DST is absent, is already an owned copy, or is one of our own symlinks left by a previous install (removed first: that is the upgrade path). A foreign file or directory is refused by name on stderr with a non-zero return, wording consistent with link_owned (scripts/lib.sh:17-30); --force additionally replaces a *foreign symlink*, never a real file or directory. On success it writes a receipt, and a copied directory tree additionally carries .nova-stamp.json (name, version, builtAt, sourceRoot, contentDigest) so a destination is self-describing without its receipt. - owned_copy DST — true when a receipt exists for DST and the destination's current digest still matches the recorded one. - uninstall_owned DST — removes DST and its receipt only when owned_copy; otherwise leaves it and prints left <DST> (not ours), matching unlink_owned's wording (scripts/lib.sh:33-37) so the two can never disagree. - installed_version DST — prints the recorded version, empty when there is no receipt. - nova_state_dir / nova_share_dir — print ${NOVA_STATE:-$HOME/.local/state/nova} and ${NOVA_SHARE:-$HOME/.local/share/nova}. Receipts live under $(nova_state_dir)/receipts/, one JSON file per destination, recording destination, kind (file or tree), digest, version, source path and install time. The share dir is where later issues put the durable Claude and Codex marketplace trees. Deriving both from $HOME is what keeps the throwaway-HOME tests hermetic and lets bootstrap-plugins.sh --uninstall read a receipt bootstrap-tools.sh --install wrote. - report_unowned (scripts/lib.sh:92-100) also treats an owned copy as managed, so an uninstall does not report our own destination as kept-unmanaged.

## Constraints

- bash 3.2, no GNU-only constructs: scripts/tests/test_install.sh:86 greps scripts/*.sh for mapfile, find -printf, readlink -f and sed -i and must stay green. Digests go through one helper picking shasum -a 256 or sha256sum. Receipts may be read with jq — it is a required core tool (bootstrap-tools.sh:50) — but must be *written* with plain shell so a partial bootstrap cannot deadlock on the tool it is installing. - A tree digest is computed from the sorted list of relative-path plus per-file digest lines, stable across machines and inode order. - set -euo pipefail is in force in every caller; helpers return non-zero rather than exit, exactly as link_owned does. - Tests go into scripts/tests/test_install.sh as a new section — it is the documented home for installer behaviour (README.md:234) and CI already runs it.

## Verification

``sh bash scripts/tests/test_install.sh shellcheck -S warning scripts/*.sh ``
