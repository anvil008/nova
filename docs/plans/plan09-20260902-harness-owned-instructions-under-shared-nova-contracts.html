Harness-owned instructions under shared Nova contracts

GOAL: replace shared prompt bodies with four generated, self-contained harness families. Claude Code, Codex, Antigravity (agy), and Grok Build retain identical machine-readable contracts for every skill and agent (name, /nova:<skill> invocation, specifier seal -> builder -> reviewer -> integrator gates, anvil.agent-handoff/v1, and acceptance oracle), while each harness owns procedure prose, prompting style, native feature use, agents, skills, and runtime scripts/hooks. Shared Nova scripts, tools, resources, and non-prompt code remain shared.

GROUND TRUTH: scripts/sync-agents.py expands agents/bodies/*.md into four mostly byte-identical agent families using variables and only-blocks; skills/<name>/SKILL.md is one body copied verbatim by every stager. agents/models.json routes ten roles and records missing per-agent surfaces. evals/run_evals.py supports only Claude and Codex behavioral executors. The merged plan08 build-{claude,codex,agy,grok}-plugin.py stagers already create symlink-free dist/<harness> trees, but read shared skills and current generated agents. ADR 0023 remains the deployment authority. PR #146 adds only plan08 artifacts and is ignored.

VERIFIED SOURCES (2026-09-01/02): OpenAI GPT-5.6 at https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6; Claude Fable 5.1, Opus 5, and Sonnet 5 under https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/; Gemini 3.7 Flash and prompt strategies at https://ai.google.dev/gemini-api/docs/latest-model and https://ai.google.dev/gemini-api/docs/prompting-strategies; Antigravity Teamwork/subagents at https://www.antigravity.google/docs/teamwork/ and https://antigravity.google/docs/subagents; Grok Build overview, skills, workflows, settings, and headless guidance under https://docs.x.ai/build/, matching the vendored ~/.grok/docs/user-guide/.

DESIGN TWICE: Candidate A keeps contracts and four bodies artifact-local under skills/<name> and agents/<name>. It has artifact locality but scatters one harness setup and repeats assembly across stagers. Candidate B, selected, creates one deep generation seam: shared contracts/manifests and shared resources feed sync-agents.py plus sync-skills.py; harness sources and tracked generated inputs live under harnesses/<h>/{agents,skills,runtime}; stagers consume only that harness root. Its interface is contract + resolved guide/roster + harness body -> generated setup, deletion would smear validation/parity/omission logic across four stagers, and locality matches the requested four-box architecture plus safe ownership seams. A marked legacy fallback is allowed only during migration; the final gate rejects it.

EXECUTION NOTES (binding): every specifier, builder, reviewer, and integrator runs headlessly. Execution: headless Antigravity (agy), model gemini-3.7-flash, effort high, via the use-other-harness skill; issues within a wave run in parallel, one workspace each. Each issue is sized for one run well under one hour. Sealed tests and shared contracts cannot be weakened.

ASSUMPTIONS: extracts are concise attributed summaries, not vendor-page copies; freshness compares normalized article content, not navigation chrome; live freshness is a loud gate while unit tests use local fixtures; unsupported optional features are omitted with generated notes, missing required values fail; paid/interactive native features never replace the headless compatibility path.

02

Architecture

◇
current + proposed — compare the smallest meaningful system boundary, then state the operational change in plain language.

Shared Nova contracts

Canonical compatibility facts and required/optional variables for 16 skills and 10 agents.

Model guide registry

Attributed extracts with official URL, fetch date, normalized digest, and refetching freshness gate.

Harness source families

Claude, Codex, agy, and Grok own agent prose, skill prose, and native runtime adapters.

Generators

Compose contracts, roster guides, harness bodies, shared resources, and limitation notes; --check detects drift.

Harness evaluators

Load one generated family, execute four native headless adapters, and reject compatibility drift.

Distribution stagers

Produce ADR-0023 self-contained dist/<harness> copies only from that harness's generated root.

Shared Nova implementation

Skill scripts, guards, tools, templates, and other non-prompt product code stay shared.

What changes

One shared skill body and one mostly shared agent body currently flow through four stagers. The target separates immutable contracts and shared resources from harness-owned bodies/runtime, generates a complete tracked input tree per harness, and makes guide freshness, sync drift, contract parity, four-harness evals, and standalone staging independent gates.
