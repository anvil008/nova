Solution plan

swarm — Solution implementation plan

A versioned, fail-closed Swarm coding-fleet control plane whose parent/child authority can only narrow, whose workflow units own specialist refinement and invocation, whose exact routes and workflow evidence are machine validated, whose supervisor fences generations, budgets, cancellation and file/symbol ownership, whose Factory mutations are transactional and catalog-confined, whose Claude and Antigravity orchestrators receive only a typed lifecycle tool, and whose bounded two-pass verification behavior is proven locally and on LXC 135 without model, benchmark, scorer, gold, hidden, history, or issue-web access.

Success measures
  • Authority expansion, direct orchestrator-to-leaf invocation, ambiguous or unavailable routes, stale generations, forged results, missing proof, budget oversubscription, and ownership conflicts all reject deterministically.
  • Canonical catalog, runtime admission, Claude, Codex, and Antigravity projections express identical authority, selection, route, and evidence semantics.
  • A workflow-result envelope is accepted only when its current generation, route, authority, repository snapshot, artifacts, commands, checks, and evidence obligations reconcile; process exit zero alone is never success.
  • Cancellation durably fences admission, cascades through descendants, drains processes and events, releases reservations and leases, and records late output as audit-only.
  • Factory can modify only the canonical specialist catalog, generated projections, and installer-owned harness state, with byte-and-metadata preimages, validation, rollback, and fresh-session proof.
  • The default verification policy performs two total independent verification passes with at most one targeted repair and terminates as accepted, exhausted, cancelled, blocked, or no-progress.
  • Provider-free local adapter conformance and remote LXC 135 compile, import, projection, and conformance checks pass without a model call or benchmark attempt.
  • Remote model, thinking, and message settings remain exactly google/gemini-3.7-flash, THINKING_BUDGET=65535, and message_limit=100.
  • Final independent Code Review and Coding Evaluation produce valid current-generation evidence envelopes with no unresolved high-severity finding.
Assumptions
  • The authoritative sidecar is docs/plans/solution-plan.json, SHA-256 b9fc7439413aa7c41344246706c4ff1e60ac4ab306bb806e7a0fd641c4c6eaa2, size 5,223 bytes.
  • The implementation baseline is the current 119-entry working tree: 82 tracked modifications and 37 untracked files, status digest eda32a1a4e8a2042bfe5e621f44322d1ea6139a15c45ae7110283ef5de9b352f.
  • All current runplane/ and cmd/swarm-runplane/ files are untracked user work and must be patched in place, never replaced from Git or the recovery backup.
  • controlplane/ is the selected shared-contract package; placing these contracts in runplane would invert the existing dependency from runplane to codingfleet.
  • The initial supported verification range is one or two total passes, default two. Increasing the hard maximum requires a later reviewed contract version.
  • Installed-version discovery must prove exact Claude and Antigravity MCP registration and tool names before projections are enabled. Unsupported registration blocks that adapter; it never triggers a shell fallback.
  • Nexus task import remains pending and every board_task_ref remains null until the CLI is reachable and [I###] titles are reconciled.
  • LXC mutation, promotion, and any cold reload execute only under the goal's explicit remote-operation authority and after a fresh backup manifest.
  • Every implementation, review, evaluation, and remote-operation assignment uses gpt-5.6-sol at max; no isolated task is low-risk enough to justify Terra for this scope.
Global invariants
  • Preserve HEAD and every unrelated dirty-worktree byte; reconcile overlapping files before editing.
  • Coding Orchestrator invokes only the seven peer workflow units. Workflow units alone refine and invoke technical/domain leaves.
  • No specialist pool is mandatory; an empty selected set is valid when reasons and evidence support it.
  • Research, Planner, Code Review, Debugger, and Coding Evaluation remain read-only; Executor owns target-project writes; Factory owns only fleet catalog/projection/install surfaces.
  • Authority is parent intersection canonical ceiling intersection requested narrowing intersection observed harness capability; missing or incomparable dimensions deny.
  • Provider, family, exact model, and effort never silently substitute.
  • Unknown contract fields and incompatible major versions reject.
  • Exit code zero, narrative claims, or writer-owned tests cannot independently establish completion.
  • No unrestricted shell, arbitrary executable, argv, URL, or filesystem path is accepted through the structured lifecycle tool.
  • No model or paid-provider calls, benchmark execution, scorer calls, gold patches, hidden tests/results, scorer metadata, prior solutions, history, or issue-web searches.
  • Do not touch port 8888.
  • Generated projections are changed only through codingfleet.Render/SyncRendered.
  • Remote /opt/evals/benchmarks/swe_bench_fleet.py is validation-only and must preserve t.message_limit = 100.
Out of scope
  • Product-agent feature work, GitHub App/code-review implementation, registry redesign, UI work, cloud deployment, paid evaluation, benchmark scoring, merge/push/commit, and unrelated cleanup.
  • Restoring /tmp/swarm-fixed-pipeline-backup-20260823-yfKdwZ.
  • Changing the remote model, thinking budget, message limit, benchmark data, scorer, or port 8888 service.
  • Broadening Factory into a generic target-project writer.
  • Supporting more than two verification passes in this contract version.
