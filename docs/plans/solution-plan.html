2. Executive Recommendation

Add an optional Herdr presentation transport beside the existing direct provider transport. In Herdr mode the supervisor creates a non-focused tab/root pane, launches a Swarm-owned worker using a stable argv, and exchanges ordered authenticated NDJSON over a per-job mode-0600 Unix socket. The worker launches the exact admitted provider command in its own process group and forwards streams without changing the validated anvil.agent-handoff/v1 and controlplane.WorkflowResult authority.

Leading trade-off: a dedicated worker and replayable control channel add lifecycle complexity, but they preserve exact provider semantics while giving the operator a real terminal to observe. Same-provider native harness agents remain unsupported in this slice rather than being mislabeled as visible.

3. Problem and Opportunity

The current run plane supervises headless provider processes. Herdr can show panes, but a pane alone does not expose stable task context or prove completion. Operators need to see who owns a job, its phase, and its current bounded summary without leaking prompts or letting display metadata become task truth. The implementation opportunity is to reuse the existing supervisor admission, persistence, cancellation, events, and validated handoff boundaries while changing only the process presentation transport.

4. Goals, Non-goals, and Success

Goals

  • One watchable non-focused pane per eligible foreign job.
  • Safe task metadata with deterministic replay, refresh, clear, and move resolution.
  • Ordered, authenticated, bounded worker control/result traffic.
  • Parity with direct mode for streams, send, cancel, recovery, and terminal authority.

Non-goals

  • Native same-provider adapter.
  • Closing completed panes or controlling focused UI.
  • Public arbitrary metadata mutation.
  • Replacing run-plane result authority with Herdr state.

Failure conditions

  • Brief, credentials, nonce, or provider input appears in argv/metadata.
  • Visibility failure changes job disposition.
  • Cancel kills pane shell or Herdr session.
  • Replay duplicates input or durable events.

6. Current Context

runplane.Supervisor currently owns admission, persistence, process-group creation, stream capture, send/resume/cancel, and recovery. Job persists durable lifecycle fields under schema version 2. Herdr exposes explicit layout and metadata operations, but pane IDs are opaque volatile locators. This plan keeps the public run-plane API additive at v2 while migrating on-disk state to schema 3 for durable presentation state and separate locator evidence.

9. Proposed Solution

Introduce codingfleet.AgentPresentation, durable runplane.PresentationState, volatile VisibilityLocator, a bounded herdrbridge, and an internal worker protocol. In off mode the current direct path is unchanged. In auto, eligible jobs use Herdr when all explicit prerequisites pass and otherwise remain direct with a visibility diagnostic. In required, the job is rejected before provider launch if the presentation transport cannot be established.

The supervisor is the sole publisher for source swarm:task-display. It persists a monotonically increasing sequence before each metadata patch, refresh, replay, or clear. The worker never self-reports lifecycle through Herdr. An optional distinct liveness source may describe presentation only.

12. Interfaces, Data, and UI

  • Presentation contract: taskRef 1–64 safe ASCII; task 1–80 explicit text, never copied from Brief; phase allowlist; optional summary ≤80; admitted exact model ≤80; durable attempt 1–32 and never a pane ID.
  • Metadata: at most six tokens under swarm:task-display; clear sets all six to null. Active TTL 600000; terminal TTL 3600000.
  • Worker protocol: mode-0600 claim and socket; frames hello/start/provider-started/stream/input/cancel/heartbeat/exit/ack/error with job ID and monotonic sequence.
  • Persistence: on-disk state schema migrates 2→3. Presentation state is durable; locator remains volatile and re-resolved by terminal identity plus a unique durable job label.
  • Operator UI: sidebar rows may render $task, $phase, $summary, $model, $attempt; no public mutation endpoint is added.

13. Quality, Security, and Operations

Activation fails closed on ambiguous injection. The binary path must be absolute and explicitly configured; workspace/socket/session are injected; no ambient PATH, focus, current pane, or --current. Briefs, bearer credentials, claim nonce, provider input, and raw prompts stay off argv and metadata. Worker and provider output are bounded and exact-line forwarded. Health/config surfaces report safe mode/readiness/errors only. Visibility failures remain observer failures; worker/pane loss is a transport failure. Rollout begins off, moves to auto after provider-free conformance, and uses required only for environments that intentionally reject invisible jobs.

14. Decisions and Trade-offs

DEC-001 — Accepted

Use layout.apply with argv to create a dedicated non-focused tab/root pane. Reversible by mode off.

DEC-002 — Accepted

Use an authenticated sequenced Unix NDJSON worker channel; complexity buys send/cancel/reconnect and stream parity.

DEC-003 — Accepted

Supervisor alone publishes task metadata; leaf agents never self-report lifecycle.

DEC-004 — Accepted

Persist presentation state separately from volatile locator; Herdr never becomes truth.

DEC-005 — Accepted

Support only foreign-provider jobs and require explicit Herdr injection. Native adapter is deferred.

DEC-006 — Accepted

Provide off/auto/required modes while keeping direct transport behavior and public API v2 compatible.

15. Delivery and Rollout Roadmap

ROAD-001 · Contracts and characterization

Characterize direct behavior; add safe presentation contract and schema 3 migration. Medium scope/risk. Done when prompt-off-argv, ordering, handoff, cancellation, recovery, and migration tests pass.

ROAD-002 · Bridge and worker

Add Herdr 0.8.2 bridge plus secure worker protocol. Large/high risk. Done when layout, resolve, metadata, socket, streams, input, cancel, and reconnect tests pass.

ROAD-003 · Supervisor integration

Add modes, transport selection, durable replay/refresh/clear/move/cancel/recovery. Large/high risk. Done when visibility errors cannot alter job truth and panes remain open.

ROAD-004 · Operations and conformance

Add safe config/health/docs/sidebar/rollout/rollback plus provider-free focused, race, combined, and offline tests. Medium scope/risk. Rollback is mode off and process restart; no pane cleanup is automatic.

Review boundaries: contracts/migration; bridge/worker; supervisor lifecycle; operator surface/conformance. No automatic commits.

16. Test and Validation Strategy

Characterization tests lock direct semantics first. Unit tests cover token validation, state migration, client bounds, opaque resolution, sequence/TTL/clear, frame authentication, replay windows, process groups, and error isolation. Integration tests use fake Herdr/provider binaries and Unix sockets for concurrent panes, prompt secrecy, send, cancel, reconnect, move, cold replay, and parity. Race tests cover worker/send/cancel/recover/replay/visibility/durability. The final gate runs combined package tests and offline conformance without model/provider calls.

17. Risks, Assumptions, and Open Questions

RSK-001 · High impact / medium likelihood

Protocol loss could misorder input or output. Trigger: missing sequence/ack. Mitigation: durable acceptance, monotonic frames, bounded replay; contingency: fail transport, never infer success.

RSK-002 · High / low

Cancellation could target the pane shell. Mitigation: capture and signal provider PGID only; tests inspect signals. Contingency: mode off.

RSK-003 · High / low

Secrets could leak in argv/metadata. Mitigation: claim file/socket and strict presentation schema; negative tests. Contingency: required-mode rejection.

RSK-004 · Medium / medium

Pane moves make locators stale. Mitigation: terminal identity + unique durable job label resolution; ambiguity is visibility-only.

Assumptions: Herdr 0.8.2 layout/snapshot/metadata contracts remain available through explicit injection; foreign provider CLIs retain current stdin behavior; current dirty bytes are intentional. Open item: native same-provider harness instrumentation requires a later design with its owning harness; it is not silently approximated here.

18. Final Recommendation

Deliver the foreign-provider runplane slice with worker-backed Herdr panes, safe supervisor-owned task metadata, and strict observer/authority separation. Completion means all nine requirements have current provider-free evidence, combined tests and offline conformance pass, direct mode remains compatible, and docs state the native gap. Any need to control live configuration, deploy, or broaden native harness scope requires separate authority.
